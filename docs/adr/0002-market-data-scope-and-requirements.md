# ADR-0002：行情数据范围与需求

## 状态

Accepted

## 背景

MarketSentinel 已完成阶段 0 的 Mock MVP 稳定化和阶段 1 的真实交易日历接入。当前 `MarketDataProvider` 仍由 `MockMarketDataProvider` 实现，`MarketSnapshot` 仅承载任务阶段、生成时间、事实列表和原始指标，尚不具备真实行情接入所需的证券级报价、来源时间、接收时间、完整性和新鲜度语义。

本 ADR 固化阶段 2 的行情数据范围和需求边界，不选择具体数据供应商，也不代表文中所述的真实行情、观察池、竞价采集和完整性状态已经实现。

## 一、阶段 2 当前范围

阶段 2 首版只实现 A 股真实行情数据。A 股是用户直接投资的市场，因此首版要求：

- 同时覆盖上海证券交易所和深圳证券交易所；
- 支持指数、ETF 和股票；
- 使用用户明确提供的准确证券清单；
- 不持续轮询全部 A 股；
- 支持数量受控的重点实时观察池；
- 为后续增加更大范围的分钟级、延迟或盘后筛选池保留扩展能力。

当前阶段不实现：

- 港股真实行情；
- 韩国真实行情；
- 美股真实行情；
- 新闻；
- 数据库；
- 真实 LLM；
- 券商交易；
- 自动下单。

## 二、未来观察市场

### 港股

港股与 A 股关联度高，应作为未来的重要观察市场。未来关注：

- 重要指数；
- AI、半导体、互联网及中国资产代表证券；
- A/H 股联动。

当前 `TradingMarket` 尚未实现 `HONG_KONG`。未来接入港股前，需要单独增加以下市场与交易日历映射：

```text
TradingMarket.HONG_KONG → XHKG
```

本 ADR 只记录该需求，不修改现有枚举或交易日历。

### 美国市场

未来美国市场只关注：

- 重要指数；
- 费城半导体指数；
- AI 芯片、服务器、存储及相关代表公司。

不要求广泛覆盖全部美股。

### 韩国市场

未来韩国市场只关注：

- 重要指数；
- 半导体和存储产业链代表公司。

不要求广泛覆盖全部韩国市场。

## 三、证券清单策略

证券清单不得写死在业务代码中。未来配置应支持：

- A 股指数；
- A 股 ETF；
- 当前持仓；
- 重点自选；
- 扩展观察池；
- 港股观察证券；
- 美股观察证券；
- 韩国观察证券。

建议的示例配置路径为：

```text
config/watchlist.example.yaml
```

未来真实用户配置使用：

```text
config/watchlist.yaml
```

真实用户配置不得提交到 Git。上述文件和对应加载逻辑当前尚未实现；阶段 2 首版只消费 A 股清单，其余市场仅保留设计扩展点。

## 四、两层 A 股覆盖策略

### 实时重点层

实时重点层用于：

- 实际持仓；
- 重点自选；
- 重点 ETF；
- 主要指数。

证券数量必须受数据源限额和成本约束。

### 广域筛选层

广域筛选层用于更大范围的 A 股观察，但不要求持续实时轮询。可使用：

- 分钟级批量数据；
- 延迟行情；
- 盘后数据；
- 日线数据。

该层用于生成候选池，不直接作为盘中即时交易依据。

免费、低延迟和全市场覆盖不能同时作为阶段 2 首版的硬要求。

## 五、集合竞价策略

第一版不要求连续保存 09:15—09:25 的全部变化。后续行情采集建议固定观察以下节点：

- 09:15:30：集合竞价开始快照；
- 09:20:30：中间观察快照；
- 09:25:30：最终集合竞价结果和开盘价；
- 09:35：连续竞价确认快照。

这些节点是阶段 2 的采集需求，不代表当前 scheduler 已经实现全部对应任务。当前 scheduler 的既有时间保持不变，本 ADR 不修改调度配置。

### 必需能力

- 09:25 之后的正式开盘价；
- 09:35 连续交易最新价；
- `previous_close`；
- `source_time`；
- `received_at`。

### 可选能力

如果数据源支持，则获取：

- 集合竞价参考价格；
- 匹配量；
- 未匹配量；
- 买卖方向。

如果供应商不支持这些字段，provider 必须明确标记为 `unsupported`，不得推导或虚构。完整的竞价连续采集留到后续根据实际运行效果决定。

## 六、数据源成本和授权原则

数据源选型遵循以下用户约束：

- 优先使用免费数据源；
- 可接受的月度费用上限约为人民币 200 元；
- 延迟尽量短；
- 当前不预设具体供应商。

后续数据源选型必须依据供应商官方文档，至少比较：

- 授权范围；
- 商业和个人使用限制；
- 是否为实时、延迟或盘后数据；
- 上海与深圳市场覆盖；
- 指数、ETF 和股票字段；
- 集合竞价字段；
- 调用频率和证券数量限制；
- 历史数据范围；
- macOS、Linux 和云服务器兼容性；
- 是否要求券商账户；
- 是否依赖桌面客户端常驻；
- 是否与交易权限绑定；
- 是否支持纯只读；
- 月度费用；
- 停服和退出方案。

来源不明的网页接口、网页抓取或逆向接口不得作为生产数据源。它们可以被标记为实验用途，但不得被推荐为生产方案。

## 七、个人 API 与券商 SDK

当前不对接入形式作最终选择。未来 provider 选择 ADR 必须比较：

- 独立个人 API；
- 券商行情 SDK；
- 商业数据服务；
- 本地终端网关，例如需要常驻进程的方案。

优先条件依次为：

1. 只读；
2. 无交易权限；
3. 许可清晰；
4. 数据时间明确；
5. 可在长期运行的 Linux 环境部署；
6. 提供商可替换；
7. 不把行情业务逻辑绑定到券商账户。

不得因为使用券商 SDK 而加入下单功能。

## 八、数据缺失策略

用户接受在部分证券缺失时生成不完整简报。未来行情获取结果必须区分：

- `complete`；
- `partial`；
- `failed`。

`partial` 至少记录：

- `missing_symbols`；
- `stale_symbols`；
- `provider_errors`；
- `source_time`；
- `received_at`；
- `completeness`。

处理规则如下：

- 缺少非关键证券时，可以生成 `partial` 简报；
- 缺少关键证券时，也可以生成 `partial` 简报，但必须降低置信度并突出警告；
- 数据源整体失败时，不得生成正常市场态势判断；
- 不得把 `partial` 输出伪装为 `complete`；
- LLM 和通知层必须能够看到完整性状态。

当前 `JobRunStatus` 只描述任务完成或非交易日跳过，尚未实现上述行情完整性状态。本 ADR 将其定义为阶段 2 的领域需求，不改变现有任务状态语义。

## 九、延迟与新鲜度

当前只定义以下原则：

- 目标为尽可能接近实时；
- 具体 SLA 在选定供应商后确定；
- 每条行情必须具有 `source_time` 和 `received_at`；
- 系统计算 `delay_seconds`；
- 不同 phase 未来可以具有不同的新鲜度阈值；
- 过期数据必须被明确标记或拒绝。

在尚未选定数据源时，不承诺或编造精确延迟指标。

## 十、指数策略

阶段 2 暂时保留指数，原因如下：

- 指数有助于判断市场整体状态；
- 用户也可以在交易应用中查看指数；
- 是否长期保留由实际运行效果决定。

指数清单必须配置化，不得写死在业务逻辑中。

## 十一、测试与运行方式

在数据许可允许的范围内，可以使用录制 fixture 做回归测试。阶段 2 数据源开发顺序为：

1. 通过 CLI 手工触发；
2. 使用固定 fixture 测试；
3. 进入真实数据影子模式；
4. 数据质量达标后，才允许 scheduler 使用真实 provider；
5. LLM 继续使用 Mock；
6. 通知先使用 Console；
7. 不连接券商交易能力。

provider 开发初期，scheduler 应保持关闭或仅使用 Mock。不得让尚未验证的数据源自动生成生产简报。

## 十二、后续 ADR

本 ADR 只固定范围和需求。后续分别创建：

- ADR-0003：A 股行情数据供应商选择；
- ADR-0004：MarketQuote 模型和数据质量门；
- ADR-0005：A 股集合竞价采集策略。

供应商选择必须与领域模型分离，以便未来在免费数据源和不超过人民币 200 元/月的付费数据源之间切换。

## 十三、仍需用户提供的信息

以下清单由用户未来提供，不得由模型自行猜测或生成：

1. 准确的 A 股指数清单；
2. 准确的 ETF 清单；
3. 当前持仓清单；
4. 重点自选股清单；
5. 扩展观察池规模；
6. 港股、美股和韩国未来观察清单。

## 与当前项目状态的关系

本 ADR 与当前仓库状态不存在实现层面的冲突，但以下内容是已接受的后续要求，而不是当前能力：

- 当前行情实现仍为 `MockMarketDataProvider`，尚未接入任何真实行情源；
- 当前 `TradingMarket` 只有 A 股、韩国和美国市场，尚无港股枚举及 `XHKG` 日历映射；
- 当前不存在 `config/watchlist.example.yaml`、`config/watchlist.yaml` 及其加载逻辑；
- 当前 `MarketSnapshot` 尚无证券级 `MarketQuote`、新鲜度或 `complete`、`partial`、`failed` 完整性模型；
- 当前 scheduler 尚未覆盖本 ADR 建议的全部集合竞价观察节点；
- 当前真实 LLM、数据库、新闻、券商交易和自动下单能力均未实现，本 ADR 不改变这些边界。
