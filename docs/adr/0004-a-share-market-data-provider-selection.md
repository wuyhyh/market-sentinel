# ADR-0004：A 股行情数据供应商选择

## 状态

Proposed

本 ADR 记录截至 2026-07-26 基于供应商官方资料得到的初步选择，不表示任何
候选已经通过真实交易时段验收。Tushare Pro 免费账户已经完成隔离的 capability
probe，Token 有效，但当前账户不具备首版所需的实时、ETF、分钟和集合竞价
接口权限。其他候选尚未完成账号和交易时段实测。最终接受仍需要完成本文定义
的可行性实验。

## 背景

MarketSentinel 阶段 0 已完成 Mock 执行链，阶段 1 已接入真实交易日历。
ADR-0002 已将阶段 2 首版限定为用户明确配置的少量 A 股重点证券，ADR-0003
已经接受供应商无关的 `MarketQuote`、`QuoteBatch` 和确定性数据质量门设计。

当前业务代码仍由 `MockMarketDataProvider` 直接产生 `MarketSnapshot` 和
自然语言 `Fact`，没有真实行情 provider，也没有本文候选的依赖或配置。
因此必须先比较合法来源、授权、时间语义、字段、成本和部署边界，再决定首个
真实适配器。

本次调研只采用以下官方来源：

- 供应商产品与 API 文档；
- 供应商官方价格或权限页面；
- 供应商官方用户协议。

博客、自媒体、论坛经验帖、网页抓取接口和逆向接口没有作为决策依据。官方
资料没有公开的信息一律标为未知或需要人工询价，不用非官方信息补齐。

## 用户约束

- 首版只实现上海、深圳 A 股行情。
- 直接投资对象为股票和 ETF；指数暂时保留，但不是绝对必需。
- 只监控用户明确配置的重点证券，不持续轮询全部 A 股。
- 优先免费，付费上限约为人民币 200 元/月。
- 希望延迟尽量短，但不把供应商未承诺的延迟写成 SLA。
- 部分证券缺失可以生成显式的 `partial` 简报；整体失败必须 fail closed。
- 不连接券商下单，不允许行情 SDK 获得交易权限。
- 先在 MacBook 手工验证，未来必须能在 Linux 服务器长期运行。
- 当前不实现港股、美股、韩国行情、新闻、数据库、真实 LLM 或真实通知。
- 当前 LLM 和通知继续使用 Mock / Console。

## 评估标准

候选按以下顺序评估：

1. 合法、清晰且适用于个人只读项目的数据许可；
2. 能够证明没有交易权限；
3. 沪深股票和 ETF 覆盖；
4. 能提供可审计的行情时间和 09:25、09:35、11:35、15:05 所需字段；
5. MacBook 可验证、Linux 可长期运行；
6. 免费或总成本不超过约人民币 200 元/月；
7. 接口稳定、限流可控、掉线和重连可观察；
8. 能映射 ADR-0003，且易于退出和替换。

“实时”只表示官方产品或接口使用了该名称，不等同于供应商承诺了确定的
端到端秒级延迟。最终新鲜度阈值只能根据合同、权限和交易时段实测确定。

## Tushare Pro 免费账户 capability probe

### 运行环境与验证日期

隔离 spike 于 2026-07-26 在本地 MacBook 上手工运行，环境为：

- Darwin 25.5.0 arm64；
- Python 3.12.10；
- Tushare SDK 1.4.29；
- Token 通过未提交的本地 `.env` 注入，已验证有效；
- spike 未接入 `MarketDataProvider`、`ReportService` 或 scheduler；
- 运行后的 `make verify` 通过。

该实验只探测接口能力并保存脱敏元数据，不是正式 provider，也没有证明任何
交易时段的新鲜度或稳定性。

### 实测结果

| capability | API | 结果 | 当前可支持的用途 |
| --- | --- | --- | --- |
| 交易日历 | `trade_cal` | success | 交易日历数据候选；不改变 ADR-0001 已采用的生产交易日历 |
| A 股证券基础信息 | `stock_basic` | success | 沪深证券基础信息候选 |
| 股票日线 | `daily` | success | 股票日线、离线研究和回归数据候选 |
| 指数基础信息 | `index_basic` | success | 指数基础信息候选 |
| 指数日线 | `index_daily` | success | 指数日线、离线研究和回归数据候选 |
| ETF 基础信息 | `fund_basic` | permission_denied | 免费账户不可用 |
| ETF 日线 | `fund_daily` | permission_denied | 免费账户不可用 |
| ETF 实时快照 | `rt_etf_k` | permission_denied | 免费账户不可用 |
| 指数实时快照 | `rt_idx_k` | permission_denied | 免费账户不可用 |
| 股票实时快照 | `rt_k` | permission_denied | 免费账户不可用 |
| 股票实时分钟 | `rt_min` | permission_denied | 免费账户不可用 |
| 集合竞价 | `stk_auction` | permission_denied | 免费账户不可用 |

汇总为：

```text
success=5
permission_denied=7
failed=0
```

权限不足是当前免费账户的能力边界，不是 probe 程序失败。`daily` 和
`index_daily` 成功响应中检测到的是 `trade_date`，只表示交易日期，不是盘中
交易所时间。它们不得被转换或冒充为 ADR-0003 要求的盘中
`MarketQuote.source_time`。`stock_basic` 和 `index_basic` 中的上市日期也
不是行情时间。

### 对免费账户的结论

Tushare Pro 免费账户可以继续作为以下候选：

- 证券基础信息；
- 股票日线；
- 指数基础信息和指数日线；
- 离线研究与回归数据。

Tushare Pro 免费账户不能作为：

- 唯一盘中实时行情 `MarketDataProvider`；
- 09:25 正式开盘数据源；
- 09:35 盘中确认数据源；
- ETF 实时观察数据源。

当前免费权限无法提供 ETF 数据、股票实时快照、指数实时快照、分钟行情或集合
竞价数据，因此没有证明 ADR-0002 的固定时点实时行情需求。是否购买 Tushare
付费权限暂不决定；接口出现在官方目录中不等于当前账户可用，也不等于付费后
已经满足许可、时间语义、新鲜度和预算要求。

## 二、时间能力

### 对比

| 项目 | Tushare Pro | Futu API / OpenD | JQData | QMT / MiniQMT |
| --- | --- | --- | --- | --- |
| `source_time` 候选 | 免费账户成功的股票/指数日线只有 `trade_date`，不能作为盘中 `source_time`；实时接口的 `trade_time`/`time` 因无权限尚未实测 | 快照 `update_time`；实时报价 `data_date` + `data_time`；分时记录 `time` | 分钟记录 `date`；盘后日线为交易日期 | Tick 的 `time` / `stime`，具体单位和时区需验证 |
| 官方延迟承诺 | 本次未找到数值 SLA | 本次未找到 A 股端到端数值 SLA；“实时/LV1”不能换算成秒数 | 官方接口行为表明盘中未结束当日不能由 `get_bars` 获取；盘后发布时间不等于延迟 SLA | 文档中的本地全推缓存更新频率不是端到端行情延迟 SLA |
| 09:15 | 免费账户无实时或竞价接口权限，不能提供该时点行情 | 需验证订阅是否推送有效竞价状态和时间 | 不适用当前盘中 | 需验证 Tick、状态和竞价字段 |
| 09:25 | 免费账户无 `stk_auction` 或实时快照权限，不能作为开盘数据源 | 需验证正式开盘价何时出现、时间戳和停牌行为 | 不适用当前盘中 | 需验证正式开盘字段和数据完成时点 |
| 09:30 / 09:35 | 免费账户无实时快照和实时分钟权限，不能完成盘中确认 | 快照、实时报价或订阅可用于实验 | `get_bars` 对未结束当前交易日返回前一日 | 订阅/Tick 可用于实验 |
| 11:35 | 免费账户不能完成盘中固定时点行情 | 快照或订阅缓存可用于实验 | 不适用当前盘中 | 订阅/Tick 可用于实验 |
| 15:05 | 股票和指数日线可作为盘后候选，但只有交易日期；可用时间和完成性尚未实测 | 快照或订阅缓存可用于实验 | 当日数据官方说明在 15:00 后可取，但精确可用时间需实测 | 官方问答称多数股票约 15:00:03 完成，仍需逐品类验证 |

Tushare 实时分钟接口返回分钟 `time`、OHLC、成交量和成交额，股票和 ETF
成交量单位标为股、成交额标为元；接口为单独权限。官方示例从 09:30 开始，
没有给出请求到数据产生之间的数值 SLA。[Tushare A 股实时分钟](https://tushare.pro/document/2?doc_id=374)
[Tushare ETF 实时分钟](https://tushare.pro/document/2?doc_id=416)

Futu 订阅接口支持实时报价、K 线和分时推送，也允许从 OpenD 缓存拉取。
OpenD 重连和缓存会带来“接口成功但数据可能不是当前时点”的风险，因此
`received_at` 必须由 MarketSentinel 记录，且仍须通过 `source_time` 做新鲜度
检查。[Futu 订阅行情](https://openapi.futunn.com/futu-api-doc/quote/sub.html)
[Futu 实时报价](https://openapi.futunn.com/futu-api-doc/quote/get-stock-quote.html)
[Futu 实时分时](https://openapi.futunn.com/futu-api-doc/quote/get-rt.html)

Futu 官方字段说明指出快照的更新时间是最新价更新时间，并不自动代表响应中
所有字段的更新时间。这是映射单一 `MarketQuote.source_time` 的重要协议风险，
必须用交易时段录制响应和字段变化验证，不能把一个时间戳无条件解释为所有
字段同时更新。[Futu 行情字段定义](https://openapi.futunn.com/futu-api-doc/quote/quote.html)

JQData `get_bars` 官方说明：当结束时间是尚未结束的当前交易日时返回前一个
交易日；当前交易日 09:00—15:00 的数据在 15:00 后才可获取。因此它不满足
09:25、09:35 和 11:35 的首版盘中固定快照要求。[JQData get_bars](https://www.joinquant.com/help/api/doc?id=9875&name=JQDatadoc)

QMT 官方文档中 `get_full_tick` 的 50ms 描述是客户端本地全推缓存更新方式，
不能视为交易所到 MarketSentinel 的 50ms 延迟承诺。源时间、客户端接收时间
和 MarketSentinel 接收时间仍须分别记录并实测。[QMT 行情数据问答](https://dict.thinktrader.net/innerApi/question_answer.html)

### Tushare Pro

- 需要注册账号并以 Token 鉴权；不需要券商账户或交易权限。
- 官方服务协议允许个人、非商业目的使用，同时禁止将数据用于盈利或商业
  用途。个人本地和个人云服务器长期运行是否属于所购权限允许的部署方式，
  仍应向官方书面确认。
- 股票、ETF、指数、实时分钟和集合竞价权限可能分别控制，不得把成功登录
  等同于具有全部数据权限。
- 2026-07-26 的免费账户 probe 已验证 Token 有效，同时确认 ETF、实时、
  分钟和竞价接口无权限；Token 有效不代表具备行情能力。
- Token 必须作为 Secret 通过环境变量注入，不能写入仓库、日志、异常、
  fixture 或原始响应。

来源：[Tushare 服务协议](https://tushare.pro/document/1?doc_id=405)

### Futu API / OpenD

- OpenD 登录官方说明不强制先开证券账户，可以使用 Futu ID、邮箱或手机号；
  首次登录需要完成合规问卷和协议。
- A 股 LV1 免费权限要求中国大陆身份认证，并会根据 OpenD 所在 IP 判断客户
  分类；这使本地 MacBook 和未来云服务器必须分别验证。
- 行情订阅额度与是否开户、资产和交易量分层相关。未开户或低资产档仍有基础
  额度，但额度规则可能变化；重点证券数量必须小于实测额度。
- OpenAPI 产品同时包含交易 API。采用 Futu 的必要条件不是“代码不调用下单”
  而已，而是账号和 OpenD 必须在技术上证明没有可用交易权限、没有交易解锁
  密码、没有交易账户会话，并在配置中只启用行情连接。若无法证明，Futu
  不得成为 MarketSentinel provider。
- 身份、密码、会话和设备信息属于敏感配置，不得出现在日志或仓库。

来源：[Futu 行情权限与额度](https://openapi.futunn.com/futu-api-doc/intro/authority.html)
[Futu OpenD 介绍](https://openapi.futunn.com/futu-api-doc/en/opend/opend-intro.html)

  实际合同为准。

- 不要求券商交易账户，但账号密码仍是 Secret。

## 六、与 ADR-0003 的适配

以下结论表示“官方字段可作为映射候选”，不表示适配器已经实现或字段质量已经
通过验收。

| ADR-0003 字段/语义 | Tushare Pro | Futu API / OpenD | JQData | QMT / MiniQMT |
| --- | --- | --- | --- | --- |
| `MarketQuote.symbol` / `provider_symbol` | `.SH` / `.SZ` 可规范化 | `SH.` / `SZ.` 等 provider code 需规范化 | `XSHG` / `XSHE` 代码需规范化 | `.SH` / `.SZ` 风格需规范化 |
| `exchange` / `market` / `security_type` | 代码后缀和基础信息可映射；品类需交叉校验 | 证券基本信息和市场字段可映射 | 证券类型和交易所可映射 | 证券字典可映射，权限返回需验证 |
| `currency` | A 股适配器固定预期 CNY，仍需响应/元数据校验 | 快照币种或市场元数据需校验 | A 股预期 CNY，需元数据校验 | 需按接口元数据校验 |
| `source_time` | 免费账户成功的 `daily`/`index_daily` 只有 `trade_date`，只能表达交易日期，不能冒充盘中交易所时间；实时字段尚未获得权限验证 | `update_time` / `data_time` 可用，但不代表所有字段同时更新 | 盘后/历史时间可用，盘中不适用 | `time` / `stime` 可用，单位和时区需验证 |
| `received_at` | 由 MarketSentinel 在收到响应时记录 | 同左；不能使用 OpenD 缓存读取时间代替 | 同左 | 同左 |
| `previous_close` | `pre_close` | `prev_close_price` / `last_close` | 日线可取；分钟字段语义需谨慎 | `lastClose` |
| `open/high/low/last` | `open/high/low/close`，其中 `close` 表示最新价 | 快照或实时报价直接提供 | 历史/盘后可提供 | Tick/K 线可提供 |
| `volume` | 实时股票/ETF页面明确为股 | 字段可取，单位必须 contract test | 股票数据页存在 `volume`，停牌填充行为需防护 | 字段可取，但不同接口的股/手单位必须 contract test |
| `turnover` | `amount` 明确为元 | `turnover` 可取，单位需 contract test | `money` 可取 | `amount` 可取，单位需 contract test |
| `trading_status` | `rt_k` 不含统一停牌/无成交状态；需要官方停复牌数据或字段规则组合，实时语义不足 | 有停牌字段和证券状态，映射最直接 | `paused` 可用，但官方数据可能对停牌价格做前值填充，必须禁止将填充值当最新价 | `stockStatus` 可用，枚举和时点需 contract test |
| `QuoteBatch.completeness` | 四个候选都不直接产生项目领域完整性；必须由 provider 记录逐证券错误，再由质量门计算 | 同左 | 同左 | 同左 |
| `provider_errors` | 将超时、限流、权限、空响应、字段错误脱敏映射 | 还需映射 OpenD 掉线、订阅失败、缓存过期、额度不足 | 将登录、额度、权限和协议错误映射 | 还需映射客户端未启动、数据中心断开、订阅失效和本地数据缺失 |

JQData 官方股票数据说明存在停牌数据填充行为。适配时必须读取并尊重暂停状态，
不得把前值填充后的价格当作真实最新成交价，否则会违反 ADR-0003 的停牌和
无成交规则。[JQData 股票数据](https://www.joinquant.com/help/data/stock?f=home&m=footer)

无论选择哪个候选，`received_at`、`requested_symbols`、`missing_symbols`、
`invalid_symbols`、`stale_symbols`、`provider_errors` 和最终
`completeness` 都必须由 MarketSentinel 构造。供应商返回成功不能自动转换成
`complete`。

## 七、主要风险

| 风险 | 表现 | 控制与退出条件 |
| --- | --- | --- |
| 数据许可 | 个人使用、云端长期运行、缓存、录制 fixture 或派生简报不在授权范围 | 上线前取得官方书面许可；不能确认则淘汰 |
| 字段缺失 | ETF、指数、停牌、无成交或竞价缺少必要字段 | 固定证券和 phase 做 contract test；缺字段进入 unsupported/partial，不推导 |
| 单位差异 | 成交量可能为股或手，成交额可能为元、千元或其他单位 | 每个 endpoint 以官方说明和固定响应验收；无法证明单位则拒绝 quote |
| 时间戳缺失或语义不一 | 只有交易日期、快照时间只代表最新价、缓存返回旧值 | 保留 `source_time` 和 `received_at`；时间语义不可信则协议错误或 failed |
| 调用限频 | 请求频率、订阅数量、历史额度或单次证券数超限 | 重点观察池设硬上限；记录 429/额度错误；不以无数据伪装成功 |
| 权限突然变化 | 免费权限、品类或接口被收回 | 启动时能力探测、运行时授权错误 fail closed、保留第二 provider fixture |
| 客户端掉线 | OpenD、MiniQMT 或数据中心进程仍在但行情停止更新 | 监测 `source_time` 单调性和年龄；自动重连不能跳过质量门 |
| 账号登录依赖 | 密码、合规问卷、设备验证、IP 分类或定期重新登录 | 明确人工恢复手册；无法无人值守恢复时不进入 scheduler |
| 交易权限污染 | 行情 SDK 同时暴露下单或使用有交易能力的账号 | 只读身份和进程隔离为硬门；无法证明无交易权限则淘汰 |
| 供应商锁定 | provider code、缓存、错误和数据模型渗入业务层 | 只在适配器边界转换为 ADR-0003；业务层不得导入供应商类型 |
| 退出成本 | 历史数据、原始响应或测试 fixture 受许可限制，替换时无法迁移 | fixture 只保存许可允许的最小脱敏样本；保留合成 contract fixture |
| 价格或额度变化 | 免费层减少或总价超过预算 | 每次续费前复核；超过约 200 元/月时停止自动续用并重开选型 |

供应商协议和权限页面都可能变更。版本固定只能稳定客户端行为，不能固定服务端
许可、字段或价格；provider 必须把授权失败、协议错误、限流和数据过期变成
结构化错误，不能静默降级为 Mock 或工作日估算。

## 八、初步推荐

### 第一版主候选：Futu API / OpenD

Futu 进入第一轮主实验，理由是：

- 中国大陆身份认证客户的 A 股 LV1 在当前官方权限表中为免费；
- 官方接口覆盖快照、实时报价、实时 K 线、分时和推送；
- 核心价格、量额、前收、停牌和证券状态字段较接近 ADR-0003；
- OpenD 官方同时支持 macOS 和 Linux 服务器命令行运行；
- 基础订阅额度足以容纳“小量明确配置的重点证券”的实验。

这不是最终选定。以下任一项不通过即停止采用：

- 无法使用不含交易账户或不可交易的身份；
- OpenD 无法在技术上关闭、隔离或证明不存在交易权限；
- 云服务器 IP 导致 A 股权限失效；
- 09:25、09:35、11:35、15:05 的时间、字段或新鲜度不合格；
- ETF 或必要指数不在实际免费权限内；
- 官方许可不允许个人 Linux 服务器长期只读运行。

### Tushare Pro 免费账户：离线和基础数据候选

Tushare 免费账户已经完成第一轮隔离能力实验。它的纯数据服务边界清晰，没有
本地行情网关，适合作为证券基础信息、股票日线、指数基础和指数日线以及离线
研究与回归数据候选。

但免费账户缺少 ETF、股票实时快照、指数实时快照、实时分钟和集合竞价权限，
不能承担唯一盘中实时 provider，也不能满足 09:25、09:35 或 ETF 实时观察
需求。股票日线和指数日线只有交易日期，不能补作盘中 `source_time`。

是否购买 Tushare 付费权限暂不决定。只有取得不超过预算的明确报价、许可允许
目标部署，并对实时字段、交易时段可用性和新鲜度完成新的实验后，付费 Tushare
才可以重新进入盘中 provider 比较。当前 spike 工具不会因此转为正式 provider。

### 不推荐作为首版

#### JQData

JQData 适合继续作为历史或盘后数据候选，但不推荐承担首版盘中 provider。
官方 `get_bars` 对未结束的当前交易日返回前一交易日，不能满足 09:25、
09:35 和 11:35 的固定快照。价格、云端许可和当前客户端支持矩阵也需要人工
确认。除非官方提供另一个具有明确盘中时间语义的正式产品并通过实验，否则不
进入首版实现。

#### QMT / MiniQMT

QMT/MiniQMT 有较强实时和订阅能力，但不推荐作为首版：

- 当前官方资料没有给出 macOS 客户端支持，阻碍 MacBook 首轮验证；
- 普通形态依赖客户端或数据中心常驻；
- 券商版可能与交易账户、资金门槛和交易模块绑定；
- Linux 纯数据版要求投研专业版以上，价格未公开；
- Token、客户端登录、数据中心、订阅恢复和本地数据状态增加运维复杂度。

只有在取得价格合规的 Linux 纯 `xtdata` 授权、明确无 `xttrade`、MacBook
验证问题有合规解决方案，并通过全部字段与时点实验后，才重新评估。

## 九、需要实测的未知项

### 所有候选

- 准确的用户股票、ETF 和可选指数清单是否全部有权限和一致代码映射；
- 个人本地与个人 Linux 云服务器长期运行、缓存和录制最小 fixture 的许可；
- `source_time` 的精度、时区、字段覆盖范围和单调性；
- 09:25、09:35、11:35、15:05 的实际可用时间和端到端
  `delay_seconds` 分布；
- 停牌、无成交、新上市、涨跌停和部分代码失败的返回语义；
- 股票、ETF、指数的成交量和成交额单位；
- 超时、限流、授权失败、账号掉线和部分响应的错误结构；
- 供应商维护或权限变化时的通知与退出流程。

### Futu

- 不开户身份能否完成合规认证并在本地/云端持续取得 A 股 LV1；
- 是否能从账号、OpenD 进程和网络层共同证明没有交易权限；
- 基础订阅额度的实际数量和订阅恢复行为；
- `update_time` 对 OHLC、成交量、成交额和状态的时间含义；
- 09:15—09:25 是否有可用竞价状态，09:25 正式开盘价何时稳定；
- 目标 ETF 和指数是否全部具备相同字段。

### Tushare

- 实时股票、ETF、指数和 `stk_auction` 权限的正式总价、有效期和调用上限；
- 是否允许个人 Linux 云服务器长期调用；
- `rt_k.trade_time` 缺失时的响应语义；
- 实时分钟和日线的发布延迟、限频和批量代码稳定性；
- `stk_auction` 在 09:26—09:29 的最早稳定时间，以及现有 09:25:30
  scheduler 时点与该接口不一致应如何在后续 ADR 处理；
- 统一停牌、无成交和证券状态如何获取。

免费账户已经解决“Token 是否有效”和基础/日线接口是否可调用的问题，但没有
解决上述付费权限、实时能力和交易时段问题。

### JQData

- 当前 JQData 正式产品价格、许可、调用额度和 Python 3.12/macOS/Linux 支持；
- 是否另有官方盘中实时产品可满足四个固定时点；
- 竞价数据的发布时间和权限；
- 停牌填充值、暂停状态和前收字段的确定性映射。

### QMT / MiniQMT

- 可用产品是否为纯 `xtdata` 且账号没有任何交易权限；
- macOS 是否有官方支持，或是否必须改变首轮验证环境；
- Linux 数据版价格、个人授权和云服务器许可；
- 沪深股票、ETF、指数与竞价字段的实际权限；
- Tick `time` / `stime`、成交量、成交额和 `stockStatus` 的精确语义；
- 客户端登录、Token 更新、重连和重新订阅能否长期无人值守。

## 十、最小可行性实验计划

实验不接 scheduler、真实 LLM、真实通知、数据库或交易模块。所有步骤先由 CLI
手工运行，并保存许可允许的最小脱敏 fixture。

### 第 0 步：许可和安全门

1. 向 Futu 书面确认个人只读项目、MacBook 与 Linux 云服务器使用边界。
2. 证明实验账号没有交易账户或任何可用交易权限；不配置交易解锁信息。
3. 向 Tushare 获取股票、ETF、指数和当日竞价权限的书面组合报价、限频与许可。
4. 任一候选无法满足无交易权限或许可不清晰，立即退出，不进入技术实验。

### 第 1 步：固定观察清单

由用户提供最小清单，至少包含：

- 一只上交所股票；
- 一只深交所股票；
- 一只上交所 ETF；
- 一只深交所 ETF；
- 一个可选上证指数；
- 一个可选深证指数；
- 一只已知停牌或无成交测试证券（若实验日期可合法取得）。

不得由模型猜测最终生产清单。实验代码只能消费临时、未提交的用户配置。

### 第 2 步：能力探测

对每个候选记录：

- 实际权限、订阅额度、调用频率和返回代码；
- provider symbol、证券类型、市场和币种；
- 前收、OHLC、最新价、量、额、交易状态；
- 供应商原始时间字段及其官方定义；
- 不支持的字段；
- 空响应、错误响应和部分代码失败。

不得把响应成功当作质量通过。

Tushare 免费账户已经完成本步骤的隔离 probe，结论见本文对应章节。该结果不
进入正式业务链。下一步进行第二轮候选实验：验证当前主实验候选 Futu API /
OpenD。该实验必须先确认许可清晰、仅提供只读行情且运行身份没有交易权限，
再验证其 A 股实时行情能力。本文原有排名仍将 Futu 列为第一版主实验候选；
“第二轮”指实验顺序，不表示 Tushare 免费账户已成为第一候选。

### 第 3 步：交易时段录制

至少在两个普通交易日进行，分别在以下时点附近手工触发：

```text
09:15:30
09:20:30
09:25:30
09:27:00
09:35:00
11:35:00
15:05:00
```

每次记录 `requested_at`、供应商响应、`source_time`、`received_at`、字段
缺失和错误，计算但不预设 `delay_seconds` 合格阈值。09:27 只在未来明确决定
评估并取得 Tushare `stk_auction` 付费权限后，用于验证其官方可用窗口；它
不是下一轮 Futu 实验已经具备的能力或要求。

### 第 4 步：失败和恢复

使用供应商允许的测试方式验证：

- 无权限证券；
- 无效但脱敏的测试 Token/会话；
- 超时；
- 限流或订阅额度耗尽；
- OpenD/客户端掉线；
- 重连后的缓存过期；
- 混合成功和失败证券。

实验必须证明整批失败不会生成正常简报，部分成功会形成显式 `partial`，
异常和日志不泄露凭证。

### 第 5 步：跨平台

1. 在 MacBook 完成相同清单和时点的手工实验。
2. 在目标 Linux 环境运行至少五个连续交易日的影子模式。
3. 影子模式只输出结构化质量结果和 Console 信息，不启用 scheduler 生产任务。
4. 比较平台间权限、IP 分类、时间、字段、掉线和恢复差异。

### 第 6 步：选择复核

以固定评分表比较：

- 许可和无交易权限是否为硬通过；
- 目标证券覆盖；
- 字段完整率；
- 各时点可用率和实际延迟分布；
- partial/failed 语义；
- Mac/Linux 稳定性；
- 总成本；
- 运维和退出成本。

只有完成复核后，才把本 ADR 更新为 `Accepted` 并锁定首个 provider。

## 十一、最终接受条件

最终供应商必须同时满足：

1. 官方书面许可允许个人项目在 MacBook 和 Linux 服务器长期只读使用。
2. 运行身份和组件没有交易权限；不能只依靠“不调用交易函数”。
3. 沪深股票和 ETF 的用户清单全部支持；指数若保留，缺失范围已获用户接受。
4. 09:25 后正式开盘价、09:35 最新价、前收、供应商时间和接收时间可稳定取得。
5. 11:35 和 15:05 固定快照通过至少五个连续交易日影子验证。
6. 股票和 ETF 的 OHLC、量、额、状态与单位能够确定性映射到 ADR-0003。
7. 竞价不支持字段显式标记为 unsupported，不推算或虚构。
8. 超时、限流、授权、协议、掉线、过期和部分证券失败可以结构化映射。
9. 整体失败 fail closed；partial 不显示为 complete。
10. 所有凭证仅通过安全配置注入，不进入仓库、日志或 fixture。
11. 当前总成本免费或不超过约人民币 200 元/月，并有明确续费条件。
12. provider 可被 Mock 或第二供应商替换，业务层不依赖供应商类型。

若没有候选同时满足全部条件，本 ADR 保持 `Proposed`，阶段 2 不接真实
scheduler，不通过降低安全边界强行接受供应商。

## 十二、退出和替换策略

- `MarketDataProvider` 边界只返回 ADR-0003 的供应商无关候选批次，不向
  `ReportService`、风险引擎、LLM 或通知层暴露 SDK 类型。
- 内部证券代码和 `provider_symbol` 分离；切换供应商只替换代码映射表和
  适配器。
- 供应商能力以结构化 capability 描述，unsupported 字段不由第二层推导。
- 错误统一映射为 ADR-0003 的领域异常，不让调用方解析供应商错误字符串。
- 合成 fixture 始终可运行；真实响应 fixture 只保留许可允许的最小、脱敏样本。
- 不依赖供应商本地历史缓存作为唯一业务记录。当前没有数据库，也不承诺保存
  原始行情。
- 保留 Mock provider 作为开发和确定性验收实现，不在真实 provider 失败时
  自动回退到 Mock。
- 若价格超预算、许可变化、交易权限无法隔离、字段时间语义失效或连续数据
  质量不达标，停止真实 scheduler，记录 failed，并切换到另一候选的影子实验。
- 退出时撤销 Token、会话和订阅，删除许可要求删除的本地缓存；不把账号或
  数据复制到新 provider。

## 十三、与现有项目的关系

本 ADR 与 ADR-0002 一致：

- 只选择 A 股少量重点证券的数据源；
- 不追求免费、低延迟和全市场覆盖同时满足；
- 允许非关键或关键证券缺失时生成显式 `partial`；
- 整体数据源失败时不生成正常市场判断；
- 初期只通过 CLI、fixture 和影子模式验证，scheduler 保持 Mock 或关闭。

本 ADR 与 ADR-0003 一致：

- 供应商响应先映射到 `MarketQuote`/候选批次，再经过确定性质量门；
- `source_time` 和 `received_at` 分离；
- 单位、时间、状态和完整性不能由 LLM 判断；
- 供应商不支持的竞价字段不推导；
- LLM 只能看到质量门之后的数据与完整性状态。

当前代码尚未实现 ADR-0003 的模型和质量门，因此本文的“可映射”只是选型条件，
不是现有能力。任何真实 provider 实现必须在模型和质量门落地之后进行。

## 十四、不在本 ADR 范围

- 修改现有 Python 业务代码、依赖、测试或配置；
- 最终接受某个供应商；
- 申请账号、购买权限、写入 Token 或登录任何客户端；
- 建立真实行情连接；
- 修改 scheduler 时间或启用真实 provider；
- 实现 ADR-0003 的 `MarketQuote`、`QuoteBatch` 或质量门；
- 确定精确新鲜度 SLA；
- 连续保存 09:15—09:25 全部竞价变化；
- 全市场 A 股持续轮询；
- 港股、美股或韩国行情；
- 新闻、数据库、真实 LLM、真实通知；
- 券商交易、自动下单或任何交易权限。
